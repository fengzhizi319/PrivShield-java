# PrivShield Java — 架构设计

## 1. 系统架构

│  │  (:5174)    │  │  (:8081)    │  │  Proxy      │                │
│  └─────────────┘  └─────────────┘  └──────┬──────┘                │

## 2. 模块划分

### 2.1 agent-sdk (隐私计算 SDK)

| 包 | 职责 |
|----|------|
| `api/` | 核心 API: MaskingApi, DpApi, KAnonymityApi, QolApi, LocalDpApi |
| `dynclassification/` | 动态分类分级引擎: 规则/NER/LLM 三层漏斗 |
| `model/` | 数据模型: PrivacyProfile, PrivacyResult |
| `util/` | 工具类: RedactUtil, FieldClassifier |
| `exception/` | 异常定义: PrivacyException |

### 2.2 agent-server (gRPC + REST 服务端)

| 包 | 职责 |
|----|------|
| `grpc/` | gRPC 服务实现: 33 个 RPC 方法 |
| `rest/` | REST Controllers: 13 个端点 |
| `service/` | 业务编排层: PrivacyService |
| `config/` | 配置加载: AgentConfig |
| `observability/` | 可观测性: Metrics, Logging |

### 2.3 console (控制台)

| 子模块 | 技术栈 | 职责 |
|--------|--------|------|
| `backend-go/` | Go 1.21 + Gin | gRPC 代理 + REST 转发 |
| `web/` | React 18 + Vite | 前端 UI |
| `scripts/` | Shell | 启动脚本集 |

## 3. 数据流

### 3.1 gRPC 路径 (高性能)

```
Client → Go Backend (gRPC proxy) → Java Agent (gRPC :50051) → SDK API
```

适用场景：Mask、DP、K-Anonymity 等高频隐私原语。

### 3.2 REST 路径 (复杂功能)

```
Client → Go Backend (REST proxy) → Java Agent (REST :8079) → PrivacyService → SDK API
```

适用场景：DynClassification、Medical Pipeline 等需要多步编排的功能。

## 4. 技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 语言 | Java 17 | 企业生态成熟，LTS 版本 |
| 框架 | Spring Boot 3.3.5 | 自动配置、Actuator、安全 |
| RPC | gRPC 1.62.2 | 高性能、强类型、流式支持 |
| 构建 | Maven | 多模块管理、依赖传递 |
| 序列化 | Protobuf 3.25.5 | 跨语言、向后兼容 |
| 前端 | React + Vite | 快速 HMR、现代工具链 |
| 后端代理 | Go + Gin | 高并发、低延迟 |
